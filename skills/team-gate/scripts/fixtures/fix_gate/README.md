# fix_gate.py fixtures

Each fixture under `_build/<name>/` is a tiny fixed-date git repository at
`repo/` plus a run directory at `state/<name>/`, generated by
`make_fixtures.py`. Regenerate with:

```
python3 make_fixtures.py            # writes to ./_build next to this file
python3 make_fixtures.py --out DIR  # writes elsewhere
```

Two generations to the same location are byte-identical except
`.git/index` and `.git/logs`, because `TEAM_FIXED_TS` (default
`2026-01-01T00:00:00Z`) pins every git commit's author and committer date
and every receipt's timestamp.

## Why the receipts are hand-rolled instead of calling gate_state.append_receipt

`gate_state.start_run()` derives `run_id` and `run.json`'s `started_at`
from `datetime.now()`, and `gate_state.append_receipt()` derives every
receipt's `timestamp` the same way. Neither can be made deterministic by
an environment variable, so calling them directly would make two
generations differ on every run. This generator instead reproduces their
exact record shape and hash algorithm by hand (same canonical-JSON
SHA-256 as `gate_state._sha256_json`), substituting `TEAM_FIXED_TS` for
the wall-clock reads. `fixtures/ship_gate/make_fixtures.py`, in this same
skill, uses the same technique for the same reason.

## Where the gate-file shapes came from

Every field name in `_discover_data`, `_run_data`, `_prove_red_data`,
`_recheck_data`, `_matrix_data`, and `_claim_check_data` in
`make_fixtures.py` was copied from the committed `run_gate.py`,
`prove_red.py`, and `claim_evidence.py`, reading the exact dict literal
each script writes to its gate file, not guessed.

## Why only six gates, not ship_gate's fourteen stages

`fix_gate.py`'s required-gates list is a strict subset of
`ship_gate.py`'s: `gates/7-discover.json`, `gates/8.json`,
`gates/9.json`, `gates/9-recheck.json`, `gates/11-matrix.json`, and
`gates/12.json`. There is no handoff chain, no parity or coverage gate,
no independent-verifier gate, no CI-mirror stage, and no final
render_evidence check, because `/team:fix` produces commits rather than
a pull request. See the module docstring in `../../fix_gate.py` for the
stage-by-stage citation into `commands/team/fix.md` and
`REVIEW-OPUS.md` section 1.16.

## The fixtures

- `all-green`: every one of the six stages passes. `check` exits 0,
  verdict `PASS`.
- `red-green-never-red`: `gates/9.json` is present but exited 1 (a real
  red-green failure: the test was never red, not a missing file).
- `recheck-hash-changed`: `gates/9.json` passes, but `gates/9-recheck.json`
  records a finding (an AST hash that changed after the red-green proof),
  so it exits 1.
- `matrix-not-met`: `gates/11-matrix.json` grades its one requirement
  `NOT MET` and exits 1.
- `claim-uncited`: `gates/12.json` records one uncited quantitative claim
  and exits 1.
- `override-covers-matrix`: the same `NOT MET` `gates/11-matrix.json` as
  `matrix-not-met`, plus an `override` receipt naming gate `"11-matrix"`.
  `check` exits 0 with verdict `PASS_WITH_OVERRIDE`, and the instruction
  text `"override-covers-matrix instruction text"` is verbatim in
  `gates/fix.json`.
- `chain-broken`: an early receipt's `detail` is mutated after the fact
  without recomputing its hash, so `gate_state.verify_chain` reports the
  chain broken. Never overridable.
- `unused-override`: every one of the six stages passes, plus an
  `override` receipt naming gate `"8"`, which never fails or is missing.
  `check` still exits 0 with verdict `PASS`, and `gates/fix.json`'s
  `unused_overrides` lists it; `"unused override: 8"` is printed on
  stdout.
- `recheck-before-proof`: every gate passes on its own file content, but
  `gates/9-recheck.json`'s own gate-result receipt was appended before
  `gates/9.json`'s, so the recheck's receipt has a lower seq than the
  proof's. `check` exits 1 naming both seqs, even though neither file's
  own recorded `exit` is non-zero.
- `no-run`: a plain git repository with no run ever started against it
  (no `.team-ship/RUN`). Both `check` and `stage` exit 2.
- `stage-query-allowed` / `stage-query-blocked`: built through stage 5
  only (`gates/12.json`, stage 6's own file, is never written, since a
  query for stage 6 never looks at stage 6's own gate). The blocked
  variant additionally omits `gates/7-discover.json`, stage 1's file.
  `fix_gate.py stage 6 --repo-root <repo>` is run directly against these,
  never `check`.

## Self-test isolation

`fix_gate.py --self-test` copies every fixture into a fresh temporary
directory before running `check` or `stage` against the copy. `check`
writes `gates/fix.json` and appends a receipt, so running it directly
against the checked-in `_build` fixtures would mutate them on every test
run; copying first is what keeps `_build` byte-identical across repeated
self-test runs.
