# VS Code adapter

Installs Coco into VS Code's native chat customization folders. No extension required —
VS Code 1.106+ reads agent skills, agent files and instruction files itself, and the
same folders are read by the Copilot CLI agent runtime.

```bash
bash adapters/vscode/install.sh
```

## What it wires

| Coco artifact | Target | Mechanism |
|---------------|--------|-----------|
| `skills/<name>/` | `~/.copilot/skills/<name>/` | symlink |
| `agents/*.md` | `~/.copilot/agents/*.md` | symlink |
| `commands/<ns>/<name>.md` | `<VS Code User>/prompts/<ns>-<name>.prompt.md` | symlink |
| `commands/<ns>/_index.md` | `<VS Code User>/prompts/<ns>.prompt.md` | symlink |
| `rules/cursor-mdc/*.mdc` | `~/.copilot/instructions/*.instructions.md` | generated |

Skills, agents and instructions go to `~/.copilot/...` because those paths are VS Code
defaults (`chat.agentSkillsLocations`, `chat.agentFilesLocations`,
`chat.instructionsFilesLocations`) *and* the folders the Copilot CLI agent runtime reads.
One install covers chat in the editor and the CLI.

Prompt files are the exception: outside a workspace's `.github/prompts`, VS Code only
reads them from the active profile, so commands are linked into `<User>/prompts` plus the
prompts folder of every profile declared in `globalStorage/storage.json` that does not
already share the default one. Profile folder names are read from that file rather than
guessed, because a profile's `location` can be a nested path such as `builtin/agents`.
Editions covered: VS Code, VS Code Insiders and VSCodium.

Commands surface as slash commands in **VS Code chat** (`/team`, `/eng-anti-pattern`).
They are not visible to the Copilot CLI agent, which reads skills, agents and instructions
from `~/.copilot` but has no prompt-file location of its own.

Two artifacts change shape on the way in:

- **Commands → prompt files.** VS Code derives the slash-command name from the filename,
  and a colon is not portable, so `commands/eng/anti-pattern.md` becomes
  `/eng-anti-pattern` rather than Claude's `/eng:anti-pattern`.
- **Rules → instruction files.** VS Code wants the `.instructions.md` extension and an
  `applyTo` glob, while the source is Cursor's `.mdc` with `globs` / `alwaysApply`. These
  are the only generated files; everything else is a symlink and never goes stale. They
  are rewritten on every run, so re-run the installer after editing a rule.

## Flags

| Flag | Effect |
|------|--------|
| `--dry-run` | Print what would happen, write nothing |
| `--systems gsd,brain` | Also install system bundles (Super Intelligence generates its SI-* commands into `~/.copilot/coco-generated/si-commands` first) |
| `--source /path/to/coco` | Link artifacts from another checkout — useful when running the installer from a git worktree that may later be removed |
| `--user-dir "<dir>"` | Add a VS Code `User` folder the detector missed (portable installs, custom `--user-data-dir`) |

`COPILOT_HOME` overrides `~/.copilot` if you keep it elsewhere.

## Verify

```bash
ls ~/.copilot/skills | head
ls ~/.copilot/agents | head
ls ~/.copilot/instructions | head
ls "$HOME/Library/Application Support/Code/User/prompts" | head   # macOS
```

Then reload VS Code (**Developer: Reload Window**) and check:

- `/` in the chat input lists the Coco commands
- **Chat: Configure Agent Skills** lists the Coco skills
- Skills also appear to `copilot` CLI sessions started from the terminal

If skills do not appear, confirm `chat.useAgentSkills` is not disabled in settings — it
defaults to `true`.

## Notes

- If you also ran the Claude Code adapter, the same skills exist under `~/.claude/skills`,
  which is another VS Code default location. VS Code lists both sources; remove one
  install if you prefer a single entry per skill.
- Uninstall with:

  ```bash
  # Run from the clone root. Do not use a contains-match such as "*/coco/*",
  # which also deletes links into any path whose name contains "coco".
  CLONE="$(pwd)"
  find ~/.copilot "$HOME/Library/Application Support/Code/User" -type l -lname "${CLONE}/*" -delete
  grep -rl "Generated by the Coco VS Code adapter" ~/.copilot/instructions | xargs rm -f
  rm -rf ~/.copilot/coco-generated
  ```

  `~/.copilot/instructions` is a VS Code default folder and may hold your own instruction
  files, so only the generated ones — which carry the marker above — are removed.
