# run_gate.py fixtures

Generated by `make_fixtures.py` into `_build/` (gitignored, regenerated on demand).

pytest is not installed on the build machine. The `all-pass`, `one-fail`, `one-skip`,
`parity-mismatch`, and `no-tests-ran` fixtures each ship a stub runner at `bin/pytest`
(checked in, executable) that prints a pytest-shaped summary line and exits with the
code the fixture's name dictates, so `run_gate.py`'s parser and exit computation are
exercised without the real tool. `--self-test` prepends that fixture's `bin/` directory
to `PATH` before invoking the `run` or `parity` subcommand. The `one-skip` stub
deliberately exits 0 (the way real pytest does for a skip-only run) so the fixture
proves that `run_gate.py` computes its own exit code rather than trusting the runner's.
The `no-tests-ran` stub prints "no tests ran" and also exits 0, proving that zero
passed, zero failed, and zero skipped is a block ("no tests collected"), never a pass.

The `runner-absent` fixture ships no stub at all, and `--self-test` restricts `PATH` to
`/usr/bin:/bin` before invoking `run`, so neither a real nor a stub `pytest` can be
found and the runner-not-found path (exit 2) is exercised.

`no-ci-config`, `lint-and-test`, `multiline-run-block`, and `only-install-steps`
exercise `discover` only, which never executes a subprocess, so none of them needs a
stub. `multiline-run-block`'s `run: |` block has `set -e` on its first line and
`pytest -q` further down; discover must scan every line of the block and select the
pytest line, never the first line. `only-install-steps` has no runner line anywhere
(only `pip install` and `echo`), so discover must exit 2 rather than select an install
line.

Two more scenarios are exercised directly by `--self-test`, not by a generated fixture
directory: `unwritable-run-dir` copies `all-pass`, `chmod 000`s the run directory
itself, and confirms `discover` fails closed with exit 2 and exactly one stderr line
rather than a traceback; `receipts-unwritable` does the same to `receipts.jsonl` alone,
confirming both the one-line failure and that the gate file `discover` had just written
is rolled back, since a gate file must never exist without its receipt. Both restore
permissions afterward.

`--self-test` also runs `evidence` on `all-pass` after `discover` and `run`, because
`run_gate.py evidence` is the only writer of `.team-ship/EVIDENCE.json`; this must be a
real end-to-end check, not merely described.

`multi-command-step` and `multi-command-one-fails` both use `bash` and `python3`, which
are real binaries on the host, not stubs: the workflow's one step has a `run: |` block
with two commands, `bash tests/smoke.sh` and `python3 check.py --self-test`, both
recognized runner shapes. In `multi-command-step` both scripts exit 0, proving discover
records both commands and run executes both. In `multi-command-one-fails`, `check.py`
exits 3, proving run names the failing command rather than only reporting a single
overall exit code. `coverage-not-applicable` has only the `bash tests/smoke.sh` command,
no pytest command anywhere, proving `coverage` reports `NOT_APPLICABLE` (exit 2) instead
of attempting to measure coverage of a non-pytest command.
