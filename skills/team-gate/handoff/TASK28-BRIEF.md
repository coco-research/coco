# Task 28: run_gate's summary parser reads unittest output

Why. The pilot repository, like many brownfield Python repositories including parts of coco, runs `python3 -m unittest`. run_gate.run parses only pytest-shaped summaries (`(\d+)\s+passed`, failed, skipped, error), so a unittest run reports zero tests and exits 1 "no tests collected" even when it passed. The fix is a second summary shape, not a stub.

Change, scoped to skills/team-gate/scripts/run_gate.py and skills/team-gate/scripts/fixtures/run_gate/. The parser recognises, in the combined stdout and stderr of one command, the unittest shape: a line `Ran (\d+) tests?` gives the total; a following line `OK` or `OK (skipped=(\d+))` gives passed = total minus skipped and failed = 0; a line `FAILED \((.*)\)` carries comma-separated `failures=F`, `errors=E`, `skipped=S`, `expected failures=X`, `unexpected successes=U`, and then failed = F + E + U, skipped = S, passed = total minus failed minus skipped minus X. When both shapes are present the pytest shape wins (a pytest run may print unittest-looking lines from a wrapped runner; state this in the docstring). The recorded summary gains `shape: "pytest" | "unittest" | "none"`. Every existing exit rule stands: failed > 0 or skipped > 0 or a non-zero real exit is exit 1; zero tests in either shape is exit 1 "no tests collected"; runner absent is exit 2.

Fixtures, following the existing stub-runner arrangement in fixtures/run_gate (a stub named for the runner placed on PATH by the self-test): unittest-all-pass (a stub `bash` test script that prints `Ran 3 tests in 0.001s` and `OK`, exit 0; expect run exit 0, summary passed 3, shape unittest), unittest-one-fail (`FAILED (failures=1)`, exit 1; expect exit 1, "failed"), unittest-skip (`OK (skipped=1)`; expect exit 1, "skipped"), unittest-zero (`Ran 0 tests` then `OK`; expect exit 1, "no tests collected"), pytest-wins (both shapes printed, pytest says 2 passed; summary shape pytest, passed 2). The bash runner shape (`bash scripts/test.sh`) is what these fixtures use in their ci.yml, so discovery selects it without a name fallback.
