# prove_red fixtures

Every fixture is a git repository generated by `make_fixtures.py` at
`<name>/_build/repo`, with the base commit SHA recorded at
`<name>/_build/BASE_SHA`. Regenerating with the same `TEAM_FIXED_TS` produces
identical commit SHAs, since every git call runs with a fixed author,
committer, and date; the only variance under `diff -r` between two
generations is `.git/index` and `.git/logs`.

**proper-red-green.** The base commit ships a subtraction bug in `src/calc.py`.
The HEAD commit fixes the bug and adds `tests/test_calc.py`, whose assertion
fails against the reverted implementation and passes against the fix. This is
the baseline case: exit 0, one test, one valid red.

**new-module-import-red.** The base commit has only a placeholder test file;
the module under test does not exist yet. HEAD adds `src/calc.py` and a test
that imports it. Reverting the implementation removes the module entirely, so
the red proof is a `ModuleNotFoundError` that resolves to the added file.

**new-symbol-in-existing-module.** The base commit's module exists but lacks
the function under test. HEAD appends the function to that already-tracked
module. Reverting drops the function but leaves the module in place, so the
red proof is an `ImportError` for a name the diff adds inside a modified path.

**assertion-in-helper.** Identical bug and fix to proper-red-green, except the
assertion is raised inside a helper function defined in the test module rather
than in the test body itself. The red proof is still a valid assertion,
because the frame that raises it is in a test path.

**never-red.** The base commit already has a correct implementation and a
passing test. HEAD only adds a second test; the implementation never changes.
Reverting the implementation to base leaves it identical to HEAD, so the new
test passes even with the implementation reverted, which prove_red reports as
never-red.

**wrong-reason-syntax-error.** The base commit's implementation has a syntax
error, a missing colon. HEAD fixes the colon and adds the test. Reverting
restores the broken syntax, so the red proof is a `SyntaxError` on import, not
an assertion, which prove_red reports as invalid-red.

**weakened-after-red.** Identical to proper-red-green at generation time. The
self-test writes the generator's separately produced
`weakened_test_calc.py`, an assertion loosened to accept two different
values, over `tests/test_calc.py` in a temporary copy of the repository,
commits it, and runs recheck, which must report the test's AST hash as
changed.

**inseparable-same-file.** The base commit is an empty `app.py`. HEAD adds
both the function and its test to that same non-test file. Because the test
and the implementation it exercises cannot be separated by path, prove_red
reports the test as inseparable and never runs it.

**mixed-valid-and-inseparable.** Combines proper-red-green's valid change with
inseparable-same-file's `app.py` change in one HEAD commit, so a single run
produces both one valid red-green proof and one inseparable test.

**not-applicable-no-new-tests.** Base as proper-red-green; HEAD changes only
`src/calc.py` and adds no test at all. The enumerated test set is empty, which
prove_red reports as NOT_APPLICABLE.

**dirty-tree.** proper-red-green fully committed, then the generator appends
an uncommitted line to `src/calc.py` without committing it. Without
`--allow-dirty`, prove_red refuses to run against an uncommitted working tree.

**unrunnable-parametrised.** Identical to proper-red-green except the test
function takes a required parameter, `value`. This machine has no
fixture-aware runner, so `_run-one` cannot call the function and reports it
UNRUNNABLE instead of pass, fail, or error.
