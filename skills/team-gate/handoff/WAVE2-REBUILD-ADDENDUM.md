# Wave 2 rebuild addendum, tasks 7, 8 and 11

This addendum is attached to the original WAVE2-BRIEFS.md section for each task when the task is rebuilt. It carries three things the first round lacked: the independent verifier's findings on the first build, the rulings the brain made after those findings, and a smoke check the builder must pass before reporting. Where this addendum and the original brief differ, this addendum wins. Where this addendum and PLAN.md section 4 differ, PLAN.md wins.

## Rules that every rebuilt script must satisfy before it is reported

1. `sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))` followed by `import gate_state` at module top. The run directory comes only from `gate_state.find_run(repo_root)`; a None result is exit 2 with one stderr line. There is no second implementation of find_run anywhere.
2. Gate files are written only under `run_dir / "gates"`. Human-facing artifacts (EVIDENCE.json, EVIDENCE.md, APPROVAL.md, stage documents, the PR body) are written under `<repo>/.team-ship/`. Nothing else is written anywhere.
3. Every gate file carries `argv`, `cwd`, `head` (from `git rev-parse HEAD` of the measured repository, never from a cache file), `exit`, `summary`, and its gate-specific fields. After writing, the script appends a `gate-result` receipt whose detail carries `gate`, `gate_file`, `gate_sha256` (sha256 of the bytes just written), `exit`, `summary`. A receipt append failure is exit 2; it is never caught and ignored.
4. Every artifact write under `.team-ship/` appends an `artifact-written` receipt with `path` (relative to the repository root) and `sha256`.
5. `--self-test` runs `make_fixtures.py` as a subprocess, then runs the script's own CLI as `subprocess.run([sys.executable, __file__, ...])` for every fixture and asserts `returncode` and, where the fixture has a named failure condition, a stderr substring that names that condition. Every fixture's failure must be caused by the condition in the fixture's name; a fixture that fails because an unrelated input file is missing is a defect in the fixture.
6. `make_fixtures.py` anchors output on `Path(__file__).resolve().parent`, accepts `--out DIR`, and pins `GIT_AUTHOR_DATE`, `GIT_COMMITTER_DATE`, and fixed author and committer names and emails from `TEAM_FIXED_TS` for any git repository it creates.
7. Fail closed: an unreadable run directory, repository, or required input is exit 2 with one stderr line, never a traceback.
8. No em dash, no section sign, no wall-clock timestamp in any rendered artifact.

Smoke check, run on each script and pasted into the report. Each of the first five counts must be non-zero, the sixth must be exactly one line number inside the `__main__` guard, and the seventh must be zero:

```
grep -c "import gate_state" <script>
grep -c "rev-parse" <script>
grep -c "append_receipt" <script>
grep -c -- "--self-test" <script>
grep -c "subprocess.run(\[sys.executable, __file__" <script>
grep -n "sys.exit" <script>
grep -cE "\.team-ship.*gates" <script>
```

## Task 7, check_artifacts.py and ship-manifest.json

Findings on the first build. The script defined its own find_run that returned the bare run id, did not walk up, and ignored TEAM_STATE_ROOT. Gate files landed at `<repo>/<run-id>/gates/handoff-N.json`. Gate files had no exit, summary, or head; git_head was always the empty string because it read a `.team-ship/.git_head` cache that nothing writes. An unwritable run directory produced a traceback and exit 1. The stage-output subcommand computed a hash and a line count and never validated anything, so an artifact with empty heading bodies and an artifact whose required heading appeared only inside a code fence both passed. A symlink at an artifact path pointing outside `.team-ship/` was followed. ship-manifest.json numbered stages 5 to 14 one too high and added a stage 15; ship.md has fourteen stages and its approval gate is unnumbered. Manifest input entries carried no requiredHeadings, so no code path enforced headings. Four of nine fixtures, including the named adversarial, exited 1 because an unrelated required input was absent.

Rulings. The manifest uses ship.md's fourteen stage numbers exactly; the approval gate is keyed `"approval"`. Both `inputs` and `outputs` entries carry `minLines`, `requiredHeadings` and `forbidTokens`, and `stage-output <n> <path>` validates with the same function as `stage-inputs`. Artifact paths are resolved with `Path.resolve()` and must remain under `<repo>/.team-ship/` after resolution; anything else is exit 1 naming the escape. A heading counts only when the line is outside a fenced block; a forbidden token counts wherever it appears. Gate file name: `gates/handoff-<n>.json` under the run directory, with `head`, `exit`, `summary`, and `violations` as a list.

Fixtures must each populate every input the invoked stage requires except the one condition under test, so that the stderr reason names that condition. The self-test asserts the reason substring for every non-zero fixture.

## Task 8, run_gate.py

Findings on the first build. No `--self-test` on the script; a substitute in make_fixtures.py resolved a wrong path and failed four of five cases. Gate files went to `<repo>/.team-ship/gates/`. Receipt appends sat inside `if run_dir:` and `except Exception: pass`, so a missing RUN pointer exited 0 with no receipt. `run` never executed the discovered command; it ran a hardcoded `pytest -q` or split a caller string on whitespace. `discover` and `parity` both wrote gates/7.json. `coverage` always exited 2 because it tested the literal word "coverage" against the stringified argv. `parity` compared presence only; the CI version was always None. `discover` listed every command with no authoritative pick. EVIDENCE.md's generated header was on line 3. A missing pytest binary mapped to exit 1.

Rulings. `discover` writes `gates/7-discover.json` with `argv` (a list produced by `shlex.split` of the chosen run step), `source`, `sourceLine`, and `pins` (tool versions read from the workflow, pyproject, package.json, or lockfile). It selects the step whose job or step name contains "test" or whose argv[0] is a known test runner (pytest, python -m pytest, npm test, vitest, jest, cargo test, go test); a lint-only step is never selected; if no step qualifies, exit 2. `parity` writes `gates/7.json`, compares local version strings with pinned strings for every tool named in the pins and the argv, and exits 1 on any absent or differing tool. `run` reads `gates/7-discover.json` from the run directory, refuses any caller-supplied command (no `--command` flag exists), executes the recorded argv list with `subprocess.run(argv, cwd=repo_root)` and never a shell, records the real exit code, parses the summary, and computes its own exit: 1 when failed > 0 or skipped > 0 or the real exit is non-zero; 2 when the runner binary is absent (FileNotFoundError) or the discover file is missing. `coverage` runs the same argv with `--cov --cov-branch` appended when the runner is pytest; if the plugin is unavailable (the output contains "unrecognized arguments: --cov" or the import fails) it writes `gates/10.json` with `status: "UNVERIFIED"` and the reason and exits 1, never 0 and never 2; otherwise it records the total percentage and exits 0. `evidence` writes `.team-ship/EVIDENCE.json` per REVIEW-OPUS.md B.2 with `head`, then imports render_evidence from the same directory and calls its render function to write `.team-ship/EVIDENCE.md`; run_gate does not render the markdown itself. Every subcommand accepts `--role builder|verifier` (default builder); the verifier role writes `gates/<n>-verifier.json` for 7-discover, 7, 8 and 10 so the builder's files are never overwritten; evidence in the verifier role is exit 2 with the reason "evidence is assembled from the builder's gates only".

Fixtures: all-pass (0), one-fail (1, stderr contains "failed"), one-skip (1, stderr contains "skipped"), parity-mismatch (1, stderr contains the tool name), no-ci-config (discover 2), lint-and-test (discover 0 and gates/7-discover.json argv[0] is pytest, never ruff), runner-absent (run 2 with PATH restricted). pytest is absent on the build machine; the fixtures that need a runner therefore ship a tiny stub runner script named `pytest` placed on PATH by the self-test that prints a pytest-shaped summary line and exits with the code the fixture dictates, so the parser and the exit computation are exercised without the real tool. The README for the fixtures states this.

## Task 11, claim_evidence.py, render_evidence.py, render_approval.py, render_pr_body.py, claim-lexicon.json

Findings on the first build. None of the four scripts had `--self-test`; none imported gate_state; none recorded head. render_evidence embedded `datetime.now` in its header, so `--check` failed on every run, and it never read EVIDENCE.json. The claim matcher searched for the literal string "759:passed" and so flagged every correct numeric claim while accepting "all tests [E1]" against an entry with failures. Number words were accepted silently. matrix graded only MET and NOT_MET. "coverage is 94%" was never extracted. The override fence was not protected against a reason containing three backticks. render_evidence.py had an em dash; the lexicon split "fully tested" into two words.

Rulings. render_evidence owns EVIDENCE.md: its render function takes the parsed EVIDENCE.json and returns the markdown text whose first line is exactly `Generated by run_gate.py from EVIDENCE.json. Do not edit; edits are detected.`; timestamps in the body come from the gate files and run.json, never from the clock; `--check` renders in memory and compares bytes; whitespace-only differences are differences. claim_evidence `check` resolves every `[E<n>]` tag to the EVIDENCE.json entry whose `id` is `E<n>`, and for each sentence in the results or evidence section extracts claims with these patterns: `(\d[\d,]*)\s+(passed|failed|skipped|tests?)`, `coverage\s+(?:is|of|at)?\s*(\d+(?:\.\d+)?)\s*%`, `(\d+(?:\.\d+)?)\s*%\s+coverage`, the phrases in the lexicon (`all tests pass`, `tests pass`, `ruff clean`, `mypy clean`, `no regressions`), and number words from one to ninety-nine plus hundred and thousand. A sentence with no tag and at least one claim is a finding `uncited`. A claim whose cited entry lacks the field is `unbacked`. A claim whose value differs from the cited field is `contradicted`; "all tests pass" is backed only when failed is 0 and skipped is 0 and exit is 0. A number word is `unverifiable` and always a finding. Every lexicon unbacked word without a tag is `unbacked-word`. Any finding is exit 1; gates/12.json lists findings with line, text, type, claim, reason. `matrix` reads requirement identifiers from PLAN.md's `requirements` and `must_haves` lists, maps each to gate files that name it in a `requirements` list or in their summary, and grades MET when every mapped gate exits 0, NOT MET when any mapped gate exits 1, UNVERIFIED when no gate maps or a mapped gate exits 2; NOT MET is exit 1, UNVERIFIED alone is exit 2. There is no PARTIAL grade: gate exits are only 0, 1 or 2, so no fourth state can arise. render_pr_body wraps the override text in a fence whose delimiter is one more backtick than the longest backtick run inside the text (minimum three), which keeps it verbatim and inert for any input. claim-lexicon.json carries multi-word phrases as single entries.

Fixtures: all-claims-backed (0), number-mismatch (1, "contradicted"), unbacked-adjective (1, "unbacked-word"), uncited-claim (1, "uncited"), number-words (1, "unverifiable"), two-claims-one-tag (1, the coverage claim named), hand-edited-evidence-md (render_evidence --check 1), whitespace-edited-evidence-md (render_evidence --check 1), missing-approval-artifact (render_approval 1 naming the artifact), requirement-not-met (matrix 1), requirement-unverified (matrix 2), override-with-markup (render_pr_body 0, fence intact), override-with-backticks (render_pr_body 0, fence uses four backticks).
