Get Coco

Coco M0

Remembers across your AI tools, so you stop re-explaining.

A memory layer that lives on your own machine. It captures what you decide, keeps the newest truth, and hands the right context back to any tool you use, with its source attached.

Who it’s for

People who switch between AI coding tools on one machine and are tired of repeating earlier decisions.

Private beta, used daily — no public download yet
Why it is special See the architecture
In the labPrivate

01 The problem

Every AI tool starts from zero

You settle a question on Monday in one tool. On Tuesday a different tool has never heard of it. Chat history stays inside its chat, and the memory features built into one product stay inside that product. So you explain the same decisions again, and sooner or later two tools act on two different versions of the truth.

Coco M0 is one memory on your machine that your tools share. They write what happened into it and read what is still true out of it.

Without a shared memory

  • You re-explain earlier decisions every time you switch tools.
  • An old statement and its newer replacement sit side by side, and the model picks one.
  • Memory lives in someone else’s cloud, tied to one product.
  • When the tool doesn’t know, it guesses.

With Coco M0

  • One memory on your machine. Every connected tool reads and writes it.
  • A newer fact retires the older one, and the history stays.
  • Built so nothing leaves your Mac. Any cloud model is an opt-in you choose.
  • It can say it has no confident answer, and answers carry their source.

02 Why it is special

The design choices that make it more than a vector store

A plain vector store remembers what sounds similar. M0 is built around what is true, what replaced what, and where each fact came from.

01

One memory, every tool

Capture comes in through hooks and plugins. Recall goes out through a local API and one MCP tool, so any MCP client can reach it. Claude Code is wired in and live. Codex, OpenCode and Cursor adapters are built and switched off.

Live: Claude CodeBuilt, off: other tools
02

It knows when

M0 keeps separate clocks: when something happened, when M0 wrote it down, and each time it was seen again. A fact is never just a vector with no date. When a fact is true out in the world is a planned fourth axis, not built yet.

LivePlanned: world time
03

The newest truth wins, and the history stays

When a newer fact about the same thing arrives, M0 closes the older one and links the two. When it isn’t clear-cut, M0 holds both and flags the contradiction instead of guessing.

Live
04

Two ways to find a memory, fused

Full-text keyword search and local semantic embeddings are ranked together by rank fusion. Recall reports how it matched, and it abstains rather than bluff when nothing clears the bar.

Live
05

Every fact keeps its receipts

Each fact stores its source and a confidence. Every re-sighting is logged as an observation instead of being silently merged. Your decisions live as plain markdown records, one file each, kept in git.

Live
06

Local-first and fail-safe

The service listens on loopback only, with a token on every route except health. Embeddings are local. Hooks never block your chat: if the service is busy or down, events wait in a local spool and replay safely.

03 Architecture

How it is built

A small local service on your machine sits between your tools and one local store. Everything below runs on loopback.

  1. 01

    Tools and hooks

    Claude Code reports session start, tool use, compaction and stop through small hooks that always exit cleanly, so a failure is logged and never blocks the chat. A prompt hook spots your rulings, corrections and delegations and queues them, and can slip a few short, relevant hits into the prompt before the model sees it.

    Other tools reach M0 through capture plugins and an MCP configuration. Those adapters are built and switched off. Any MCP client can already read through the one m0 tool.

    Live: Claude CodeBuilt, off: Codex, OpenCode, Cursor
  2. 02

    Capture and normalizer

    Every host event is mapped onto one contract: an event name becomes a row kind. Secrets are redacted before anything is queued, and folders you have denied are never captured. If the service is busy, starting or down, the capture client appends to a local spool and the service replays it later. Event ids make replay idempotent, so nothing is stored twice.

    Live
  3. 03

    Temporal fact and entity store, with a hybrid index

    Raw events become atoms, one fact per row, with subject, predicate, object, confidence, source and status. A fact can be active, quarantined (reversible, never recalled) or retracted. Repeat sightings are kept as observations. Quiet background tiers build episodes, scenes and a persona profile on a schedule.

    The index is derived: full-text search plus local embeddings, rebuilt from what is stored and never the source of truth. Model-based extraction of facts from raw conversation is built and switched off until a quality gate passes, and M0 runs without it.

    LiveBuilt, off: model extraction
  4. 04

    Conflict and supersession resolver

    A newer fact retires an older one only under strict conditions, written out in the next section. Everything else is held with a recorded reason and a link between the two facts. The database itself refuses a supersede that crosses projects or runs backwards in time.

    Live
  5. 05

    Grounded recall: API and MCP

    One loopback HTTP API and one MCP tool with modes for recall, context, work in progress, handoff and remember. Recall fuses the keyword and meaning lanes, says how a hit matched, and reports when results were withheld or the engine is not ready. A session-start bundle gives a new session its context in one call.

    Live
  6. 06

    Local storage

    One SQLite file holds events, atoms, observations and links. The vector index sits beside it as a derived file. Decisions are separate plain markdown records, one per file, committed to git, so you can read and diff your own history.

    Live

04 Time and truth

Why a vector index alone gets changing facts wrong

Plain vector search finds what sounds similar. It has no idea which of two similar statements is newer, which replaced which, or which was only ever a plan.

A plain vector index

Query: “which day do we release?”

“We release on Fridays.”matchsaid earlier
“We release on Tuesdays now.”matchsaid later

Both come back, nearly tied. The model has to guess which one still holds.

Coco M0

Query: “which day do we release?”

“We release on Tuesdays now.”currentreplaces the earlier statement · source attached
“We release on Fridays.”closedkept in history, not offered as current

The newer fact closed the older one. The old statement is still there if you ask for the history.

An illustration of the mechanism, not a transcript.

When M0 closes an older fact

  • aThe new fact is a state, not a decision.
  • bIt is about the same project, subject and attribute.
  • cIts event time is strictly later.

Only when all of that holds does the older fact close, and a supersedes link is written in the same transaction.

When it does not

  • ·Anything else is held, with the reason recorded and a contradicts link between the two.
  • ·A decision never supersedes by slot. It can retire an earlier decision only through an explicit reverse link (planned).
  • ·Database triggers refuse a supersede that crosses projects or runs backwards in time.

The current view is one shared query: active, and not superseded. An as-of-time view is built, and no route exposes it yet.

05 Recall

Memory out, with its source

Recall is hybrid by design, runs on your machine, and would rather say “not sure” than make something up.

  1. 01

    Ask

    A prompt hook, the local API or the MCP tool asks what M0 knows about the task in front of you.

  2. 02

    Two lanes

    A full-text keyword lane and a local semantic lane search in parallel. No cloud call is involved.

  3. 03

    Fuse and rank

    The lanes are fused by rank. Among decisions on the same subject, the newer one comes first and the older is marked.

  4. 04

    Answer with a source

    Each hit says how it matched and where it came from. If nothing clears the bar, M0 abstains instead of bluffing.

Push-recall in the prompt

Before the model sees your prompt, M0 can inject a few short hits from separate lanes: decisions you made, questions still open, and topic notes. The hook has a hard time limit and fails open. If M0 is slow, your prompt goes through untouched. Secrets are redacted, and the prompt itself is never logged.

Live

Built, waiting to be switched on

A sessions lane that answers “what did we do on X last week” from your own local transcripts. A constitution: the standing rules you have confirmed, rendered into one file and injected into every new chat. Recency weighting for recall. Each is built and switched off.

Built, off

06 Decisions

The ruling you made stays made

Recall alone becomes a commodity. A confirmed trail of decisions does not, so M0 keeps one as its own record.

A ledger you can read

Every decision is one plain markdown file outside the database, committed to git. A new one starts as proposed, and you confirm it or withdraw it with a reason. An active decision can later be superseded.

Contradictions are caught at the door

Confirming a decision is refused when an active one in the same scope shares a tag with it, so two rulings cannot quietly disagree. A daily, read-only check verifies that each ruling attributed to you carries a word-for-word quote from the transcript. Enforcing that check is planned.

Where it is going

Thin per-tool adapters on one published event contract, with MCP as the universal surface, so a new tool needs only a small adapter and no special logic in the service. A versioned, open export of your memory as markdown, so it can leave for any system. These are plans.

Planned

Said plainly

There is no import from or export to other memory systems yet, and none has been promised. The connector design is a proposal, not a ruling.

08 Privacy

What never leaves your Mac

Local-first is the structure of the system, not a setting.

  • Loopback only. The service binds to the local interface, and every route except health needs a token.
  • Local embeddings. The embedding address must be local. Meaning-search never calls a cloud service.
  • No cloud backend by default. With none chosen, no captured text leaves the machine. Anything that sends text off the machine is opt-in and gated.
  • Denied folders stay dark. Sessions in folders you deny are never captured, and the list is checked on every call.
  • Secrets are redacted before anything is queued, and the prompt itself is never logged.
  • Nothing trains a model. Nothing M0 holds is sent to train any model. Your live store never goes into a repository or a test fixture.

A model is optional. M0 runs with no model at all today. A small local model is the intended default, and your own API key or a company gateway are planned opt-ins.

09 Where it stands

Honest status

Private beta, used daily inside Coco Research. Nothing here is a public release.

Live

  • Claude Code capture hooks and the prompt hook
  • Local spool with idempotent replay
  • Atoms, observations, episodes and links in one local store
  • Supersession gate and contradiction holds
  • Hybrid recall over a loopback API and the MCP tool
  • Decision ledger with newest-wins recall

Built, switched off

  • Codex, OpenCode and Cursor adapters
  • Model-based fact extraction and its keep-or-drop judge
  • Sessions lane and the constitution file
  • As-of-time view and recency weighting
  • Verified install, update and rollback

Planned

  • World time for facts
  • Witness confirmation of rulings and enforced quote checks
  • Plan-lint: a warning when a plan contradicts a recorded decision
  • One adapter contract and an open export
  • Coco Teams NG on the same API

Statuses follow the engineering record of 20 October 2026. No recall, accuracy or speed numbers are published for M0.
