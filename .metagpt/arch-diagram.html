The self-evolution loop

One cycle: measure first with no model, let a model write only inside a proposal, refuse anything the guards do not clear, then let one human merge decide. Nothing reaches main without that merge.

Why this shape

Model writes once, at one stage

  • observe, validate, open and record are deterministic Python with no model call, so they are testable without the network.
  • The model's output is data, a proposal file, never a direct edit to the tree.

What stops it

Guards before branches

  • Scope: anything outside the skill tree is refused.
  • Caps: proposals per cycle, diff size per proposal, spend per cycle.
  • Counts: the repository's own checkers must pass, so a count cannot move alone.
  • A rejected diff is not proposed again for two cycles.

Cadence and secrets

Dry run in CI, real run with keys

  • Monthly workflow runs --dry-run: no model credentials in GitHub.
  • The real cycle runs where credentials exist, today the owner's machine.
  • An empty cycle is a valid result, not a failure.
